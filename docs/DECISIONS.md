# Решения и допущения

## Что решено там, где ТЗ не даёт однозначного ответа

1. **Удаление мягкое.** ТЗ разрешает удалять задачи и запрещает удалять их историю. Поэтому удалённая задача или объект скрываются, а запись и история остаются в базе. Постановщик по-прежнему может прочитать историю скрытой задачи через API.
2. **Объект с задачами удалить нельзя.** Сначала нужно удалить задачи или перенести их на другой объект. Это защита от случайной потери целой стройки.
3. **Правки задачи.** Постановщик может менять название, описание, объект и исполнителя в любом статусе, кроме «Принята». Статус при этом не меняется.
4. **Принять или вернуть задачу может любой постановщик**, а не только её автор: в ТЗ указана роль, а не автор.
5. **Исполнитель обязателен при создании задачи.** Им может быть только пользователь с ролью исполнителя. Постановщику задачу назначить нельзя.
6. **«Принята» — конечный статус.** Повторного открытия нет, потому что такого перехода нет в таблице ТЗ.
7. **Комментарий** обязателен при возврате на доработку и необязателен при остальных переходах. Текст только из пробелов и переводов строк считается пустым.
8. **Исполнитель не редактирует поля задачи**, он только меняет статус.
9. **Видимость людей.** Исполнитель видит себя и постановщиков, но не список других исполнителей. В истории хранится снимок имени на момент действия, поэтому имя прежнего исполнителя видно и без доступа к его профилю.
10. **Смена исполнителя.** Прежний исполнитель сразу теряет доступ к задаче. В истории статусов смена не записывается: ТЗ требует сохранять только смену статуса.
11. **Роль хранится в таблице профилей**, а не в данных пользователя или токене. Метаданные пользователь может менять сам, поэтому им не доверяем. Снятие роли действует сразу.
12. **Новый пользователь всегда исполнитель.** Роль постановщика назначает администратор.
13. **Объяснение для руководителя** сделано текстом, а не видео.
14. **Интерфейс.** Отдельные окна и экраны только там, где их требует ТЗ. Комментарий к возврату вводится прямо в карточке задачи, а не в отдельном окне.

## Предупреждения Security Advisor

`supabase db advisors` выдаёт пять предупреждений, ошибок нет.

- **Четыре предупреждения о функциях** `change_task_status`, `delete_task`, `delete_object`, `is_manager`: вошедший пользователь может вызывать функции с повышенными правами. Это намеренно: первые три и есть единственный путь для этих действий, и каждая сама проверяет роль. `is_manager` сообщает только роль самого вызывающего. Анонимному пользователю функции недоступны.
- **Защита от утекших паролей выключена.** По документации Supabase она доступна только на платных тарифах. Тестовые пароли сгенерированы случайно.

## Что не вошло

- Общий список задач для постановщика, поиск и фильтры. Сейчас постановщик видит задачи в карточках объектов, как описано в ТЗ.
- Восстановление пароля и управление пользователями в интерфейсе. Пользователей создаёт администратор.
- Восстановление удалённых записей через интерфейс.
- Уведомления и обновление экрана в реальном времени.
- Автотесты интерфейса. Правила базы проверяются скриптом `npm run check:security`, интерфейс проверялся вручную.

## Что учесть при эксплуатации

Бесплатный проект Supabase приостанавливается при долгом простое. Если приложение не отвечает, проект нужно снова запустить в панели Supabase.
