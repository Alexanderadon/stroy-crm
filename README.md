# Мини-CRM «Объекты и задачи»

CRM для строительной компании. Постановщик ведёт объекты и задачи, исполнитель выполняет задачи и отдаёт их на проверку. Правила доступа работают на уровне базы, поэтому действуют и при обращении к Supabase в обход интерфейса.

Стек: React, TypeScript, Vite, Mantine, React Router, TanStack Query, Supabase (Postgres, Auth, RLS), Vercel.

## Запуск

Нужны Node.js 22 и проект в Supabase.

```bash
npm install
cp .env.example .env.local
```

Заполните `.env.local`: адрес и ключи лежат в панели Supabase в разделах Project Settings → General и API Keys. Секретный ключ не должен получать префикс `VITE_`, иначе он попадёт в браузер.

Примените миграции и настройки к своему проекту:

```bash
npx supabase login
npx supabase link --project-ref <ref>
npx supabase db push --remote
npx supabase config push
```

Последняя команда отключает открытую регистрацию: настройка лежит в `supabase/config.toml`.

Создайте тестовых пользователей и демо-данные. Сгенерированные пароли запишутся в `ACCESS.local.md`, этот файл в git не попадает.

```bash
npm run seed
```

Запустите приложение:

```bash
npm run dev
```

## Проверка защиты

```bash
npm run check:security
```

Скрипт работает только с публичным ключом и настоящими логинами, в обход интерфейса: читает чужие задачи, пишет статус напрямую, подделывает историю и роль, проводит запрещённые переходы. Каждая попытка печатается как PASS или FAIL. Демо-данные не затрагиваются: скрипт создаёт свои задачи `[check]` и в конце мягко удаляет их.

## Как устроены права

| Уровень | Где | Что решает |
|---|---|---|
| Права на таблицы и колонки | `supabase/migrations/*_access.sql` | Какие действия и с какими колонками вообще разрешены |
| Политики RLS | там же | С какими строками можно работать |
| Функции | `supabase/migrations/*_functions.sql`, `*_blank_text_checks.sql` | Смена статуса и мягкое удаление с проверкой роли |
| Триггеры | `supabase/migrations/*_triggers.sql` | Правила, действующие при любой записи, и неизменяемость истории |

Статус нельзя записать напрямую: у клиента нет права на эту колонку. Единственный путь — функция `change_task_status`. Она сама определяет автора и время и в одной транзакции меняет статус и пишет историю.

Функция `getAvailableActions` в `src/lib/tasks.ts` только решает, какие кнопки показать. Окончательное решение принимает база.

## Как добавить пользователя

Регистрация закрыта, пользователей создаёт администратор: в панели Supabase откройте Authentication → Users → Add user и подтвердите email. Новый пользователь получает роль исполнителя. Чтобы назначить постановщика, выполните в SQL Editor:

```sql
update public.profiles set role = 'manager' where id = '<id пользователя>';
```

## Деплой

Деплой идёт через Vercel CLI, в переменных окружения Vercel нужны только `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Секретный ключ туда добавлять не нужно. Перед `vercel link` сохраните копию `.env.local`: команда может перезаписать этот файл.
